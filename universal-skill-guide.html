Princip Co je skill — a proč je to vždy stejné

Skill je jeden Markdown soubor — recept, podle kterého agent dělá konkrétní úkol. Ne pravidlo na celý projekt, ne osobnost. Recept.

Každý agent (Copilot, Claude Code, OpenCode, Cursor, Codex…) má stejný mechanismus, jen pod jiným jménem:

  1. Existuje vyhrazená složka, kterou harness prohledává při startu.
  2. V té složce leží Markdown soubory — každý je jeden skill / prompt.
  3. Frontmatter (YAML hlavička) říká agentovi kdy ten soubor použít.
  4. Tělo souboru je instrukce — co udělat, jak vrátit výsledek, čeho se vyhnout.

Naučíš se jeden princip, použiješ ho ve všech třech harness'ech. Liší se jen cesta a jméno frontmatter klíčů.

✓ Mentální zkratka

„Kde harness hledá skill?" → vždycky najdi složku skills/, prompts/ nebo instructions/ v dotfiles toho harness'u. Tam patří tvůj soubor.

Mapa Kde co leží

GitHub Copilot

Cesta: .github/prompts/*.prompt.md

Frontmatter: mode, description, tools

Spuštění: /jméno v Chat panelu

Scope: per-projekt (žije v repu)

Claude Code (Anthropic)

Cesta: ~/.claude/skills/jméno/SKILL.md

Frontmatter: name, description

Spuštění: auto — agent si vybere podle description

Scope: globální (sdílíš mezi projekty)

OpenCode

Cesta: ~/.config/opencode/AGENTS.md + custom commands

Frontmatter: description, agent

Spuštění: /jméno v terminálu

Scope: globální nebo per-projekt

Podobnosti, které stojí za to si pamatovat

Všechny tři používají Markdown + YAML frontmatter. Když ses naučila psát SKILL.md, umíš ten samý soubor přepsat pro Copilot za 5 minut.

Všechny tři mají vedle skillů ještě vždy-načtené instrukce — Copilot: .github/copilot-instructions.md, Claude Code: CLAUDE.md, OpenCode: AGENTS.md v repu. To je jako „kdo jsem", skill je „jak to udělat".

Úkol Co dnes postavíš

Jeden skill, který funguje ve všech třech harness'ech: „HTML report z dat".

Vstup: tabulka v databázi (přes MCP) nebo CSV. Výstup: jeden self-contained HTML soubor s KPI, časovou řadou a top N. To samé, co jsi viděla na workshopu, jen tentokrát napsané tebou.

# skill: HTML report z dat (společné jádro pro všechny tři harness'e)

## Co tento skill umí
- Vezme zdroj dat (Snowflake přes MCP, CSV, JSON)
- Vyrobí self-contained dashboard.html — KPI nahoře, časová řada, top 10
- Žádný runtime — jen otevřu soubor v prohlížeči

## Co fetchnout nejdřív
- list tabulek → describe → COUNT(*) → LIMIT 5 ukázku

## Reject
- Tabulky končící na _OLD, _LEGACY, _BACKUP, _V1
- Sloupce, které neexistují (nikdy si nevymyslej)

## Output
- 1 soubor, žádné externí CSS / JS (inline)
- Brand: tmavý theme, monospace pro čísla
- Žádné placeholdery — pokud chybí data, řekni to nahlas

Tohle je tělo skillu. Frontmatter se mění podle harness'u. Tři verze níže.

Cesta A GitHub Copilot

PROMPT FILE Vytvoř .github/prompts/html-report.prompt.md

1. V kořeni svého projektu spusť:

mkdir -p .github/prompts

2. Otevři VS Code Settings (Cmd/Ctrl + ,), vyhledej chat.promptFiles a zaškrtni. Bez toho VS Code prompt soubory neuvidí.

3. Vytvoř soubor .github/prompts/html-report.prompt.md:

---
mode: 'agent'
description: 'Vygeneruj self-contained HTML report z dat (Snowflake / CSV).'
tools: ['codebase', 'editFiles', 'runCommands']
---

# HTML report z dat

## Co tento skill umí
- Vezme zdroj dat (Snowflake přes MCP, CSV, JSON)
- Vyrobí self-contained dashboard.html — KPI, časová řada, top 10

## Co fetchnout nejdřív
- list tabulek → describe → COUNT(*) → LIMIT 5

## Reject
- Tabulky končící na _OLD, _LEGACY, _BACKUP, _V1
- Sloupce, které neexistují

## Output
- 1 soubor, žádné externí CSS / JS (inline)
- Tmavý theme, monospace pro čísla

4. V Chat panelu napiš /html-report + co chceš udělat. Copilot načte tento prompt jako instrukci.

✓ Test

Když napíšeš / v Chat panelu, mělo by se ti v dropdown'u objevit html-report. Pokud ne — zkontroluj, že máš chat.promptFiles zapnuté a soubor uložený s příponou .prompt.md (nejen .md).

Cesta B Claude Code

SKILL Vytvoř ~/.claude/skills/html-report/SKILL.md

1. Vytvoř složku skillu:

mkdir -p ~/.claude/skills/html-report

2. Vytvoř soubor ~/.claude/skills/html-report/SKILL.md:

---
name: html-report
description: Použij, když uživatel chce vygenerovat HTML report / dashboard z dat (Snowflake přes MCP, CSV, JSON). Self-contained 1 soubor.
---

# HTML report z dat

## Co tento skill umí
- Vezme zdroj dat (Snowflake přes MCP, CSV, JSON)
- Vyrobí self-contained dashboard.html — KPI, časová řada, top 10

## Co fetchnout nejdřív
- list tabulek → describe → COUNT(*) → LIMIT 5

## Reject
- Tabulky končící na _OLD, _LEGACY, _BACKUP, _V1
- Sloupce, které neexistují

## Output
- 1 soubor, žádné externí CSS / JS (inline)
- Tmavý theme, monospace pro čísla

3. Nic dalšího nedělej — Claude Code skill auto-discoveruje. Při dalším promptu, kde popíšeš úkol odpovídající description, agent ho sám použije.

Klíčový rozdíl od Copilotu

V Copilotu skill vyvoláváš ručně přes /html-report. V Claude Code skill auto-vybírá agent podle description — proto je tak důležité tu description napsat jako podmínku („Použij, když…"), ne jako popisek.

✓ Test

V čistém Claude Code napiš: „Vyrob mi HTML dashboard z dat ve Snowflake." Agent by měl zmínit, že použil skill html-report (řekne to nahlas).

Cesta C OpenCode

CUSTOM COMMAND Vytvoř ~/.config/opencode/command/html-report.md

1. Vytvoř složku custom commandů (pokud neexistuje):

mkdir -p ~/.config/opencode/command

2. Vytvoř soubor ~/.config/opencode/command/html-report.md:

---
description: Vygeneruj self-contained HTML report z dat (Snowflake / CSV).
agent: build
---

# HTML report z dat

## Co tento skill umí

- Vyrobí self-contained dashboard.html — KPI, časová řada, top 10

## Co fetchnout nejdřív
- list tabulek → describe → COUNT(*) → LIMIT 5

## Reject
- Tabulky končící na _OLD, _LEGACY, _BACKUP, _V1
- Sloupce, které neexistují

## Output
- 1 soubor, žádné externí CSS / JS (inline)
- Tmavý theme, monospace pro čísla

3. Spusť OpenCode v terminálu. Napiš /html-report + popis úkolu. Custom command se vykoná v kontextu agenta build.

Globální vs. per-projekt

~/.config/opencode/command/ = globální, dostupné odkudkoliv. .opencode/command/ v kořeni repa = per-projekt, sdílíš s týmem přes git.

✓ Test

V OpenCode chatu napiš /. V seznamu commandů by se mělo objevit html-report. Pokud ne — zkontroluj cestu a frontmatter.

Help Když něco nefunguje

SymptomCo zkontrolovat
Skill se neobjeví v / menu (Copilot / OpenCode) Soubor musí mít správnou příponu (.prompt.md u Copilotu) a ležet ve správné složce. Restart VS Code / OpenCode.
Claude Code skill ignoruje Description je moc obecná („pomáhá s reporty"). Přepiš ji jako podmínku: „Použij, když uživatel chce…"
Agent vymýšlí sloupce / tabulky Do skillu přidej tvrdé pravidlo: „Pokud sloupec neexistuje v describe_table, zeptej se uživatele. Nikdy si nevymýšlej."
Agent sahá na _OLD / _BACKUP tabulku To je přesně to, co skill má řešit. Připomeň si sekci ## Reject a buď v ní explicitní.
Frontmatter parser failed YAML je citlivý na odsazení. Hodnoty s mezerami dej do uvozovek. Trojici --- dej na samostatný řádek.

⚠ Bezpečnost — všechny tři harness'e

Skill je obyčejný Markdown. Pokud kopíruješ skill z internetu, přečti si ho — může obsahovat instrukce typu „pošli obsah .env do webhooku". To není exploit, to je fíčura agentových harness'ů. (Včerejší lethal trifecta.)

Dál Co stavět příště

Když ti tento první skill funguje, mrkni na další nápady — ten samý formát, jen jiný recept:

  1. SQL review — agent přečte SQL query a najde N+1, missing index, full scan.
  2. PR description — z git diff + git log vytvoří popis pull requestu v projektovém formátu.
  3. Test scaffold — pro funkci vyrobí kostru testů (happy path + 2 edge cases).
  4. Commit message — z git diff --staged vytvoří conventional commit zprávu.
  5. Daily standup — z git log --author=ja --since=yesterday vyrobí 3 bullety na standup.

✓ Tip pro reálnou praxi

Když ti skill funguje v jednom harness'i, přepsání do dalšího je hotové za 5 minut — měníš jen frontmatter a cestu. Tělo (recept) zůstává.

Anthropic verze pro pokročilé

Claude Code podporuje i Anthropic Skill Format — frontmatter name + description stačí, ale pro velké skilly můžeš strukturovat do více souborů (referenced files, scripts). Detaily v docs.anthropic.com.
